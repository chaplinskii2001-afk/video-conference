## Как работает `min_new_tokens`

```
Параметр: min_new_tokens=max(100, int(max_tokens * 0.8))

Для max_tokens=800 (standard):
  min_new_tokens = max(100, 640) = 640
  → Модель ОБЯЗАНА сгенерировать минимум 640 токенов

Для max_tokens=1200 (protocol):
  min_new_tokens = max(100, 960) = 960
  → Модель ОБЯЗАНА сгенерировать минимум 960 токенов

Для max_tokens=7000 (merge):
  min_new_tokens = max(500, 5600) = 5600
  → Модель ОБЯЗАНА сгенерировать минимум 5600 токенов

Результат:
- Модель не может остановиться раньше min_new_tokens
- Это гарантирует достаточно полный выход
- Максимум все еще ограничен max_new_tokens
```

## Потенциальные проблемы и решения

### Проблема 1: CUDA out of memory
**Признак:** `CUDA out of memory` ошибка
**Решение:** Уменьшить max_length в коде (18000, 20000, 24000)

### Проблема 2: Все еще обрезано
**Признак:** Логи показывают сгенерировано < min_new_tokens
**Решение:** Перестроить Docker образ (`docker-compose build --no-cache`)

### Проблема 3: Warning о конфликте параметров
**Признак:** "Both max_new_tokens and max_length seem to have been set"
**Решение:** Это старая версия, проверить что изменения применены

## FAQ

**Q: Почему `min_new_tokens` имеет значение 80% от max?**
A: Это баланс между гарантией минимального выхода и экономией GPU памяти. 80% достаточно для полного содержания.

**Q: Почему увеличили max_length при токенизации?**
A: Чтобы дать модели больше контекста для анализа. Для коротких файлов это критично.

**Q: Почему разные min_new_tokens для разных методов?**
A: Для summarize_chunk мин 640 достаточно, для merge_summaries нужно 5600+ для полного документа.

**Q: Можно ли еще больше увеличить max_length?**
A: Да, если GPU позволяет. Проверьте max_position_embeddings Qwen (обычно 32768).

**Q: Почему Transformers выбирает max_new_tokens вместо max_length?**
A: Для causal language models это стандартное поведение. max_new_tokens более предсказуем.
