# Исправление проблемы обрезания суммаризации для коротких файлов

## Проблема

При обработке **коротких** видео/аудио файлов, краткое содержание (summary) было **обрезано/сокращено**, как будто не хватало токенов для полного вывода. Однако при обработке **длинных** файлов такой проблемы не было.

### Симптомы
- Краткое содержание для файла ~5-10 минут было неполным
- Краткое содержание для файла ~30+ минут было полным
- Код лог показывал, что генерация завершилась, но вывод был усечен

## Анализ

### Исследование кода

В методе `summarize_chunk()` (video_processor.py, строки 429-443):

```python
# ДО ИСПРАВЛЕНИЯ
inputs = self.model_manager.qwen_tokenizer(
    prompt,
    return_tensors="pt",
    truncation=True,
    max_length=12000  # <-- ПРОБЛЕМА ЗДЕСЬ
).to(self.model_manager.qwen_model.device)

with torch.no_grad():
    outputs = self.model_manager.qwen_model.generate(
        **inputs,
        max_new_tokens=max_tokens,  # 800 для "standard"
        do_sample=False,
        num_beams=1,
        repetition_penalty=1.05,
        # <-- ОТСУТСТВОВАЛ явный max_length!
    )
```

### Причина проблемы

1. **Проблема #1: Ограничение входной последовательности на 12000 токенов**
   - При токенизации, весь prompt + текст обрезается до 12000 токенов
   - Для КОРОТКИХ файлов: prompt с системным сообщением занимает значительный % от 12000
   - Это оставляет мало "контекста" для модели для обработки

2. **Проблема #2: Отсутствие явного max_length в generate()**
   - Метод `generate()` не имел явного параметра `max_length`
   - Это означало, что модель могла завершить генерацию раньше положенного
   - Для Qwen модели, завершение может быть вызвано внутренними ограничениями

3. **Почему это по-разному влияет на короткие и длинные файлы:**
   - **Длинные файлы**: Весь входной текст занимает близко к 12000 токенам, модель имеет много контекста
   - **Короткие файлы**: Входной текст намного меньше (например, 2000 токенов), модель может "видеть" задачу как неполную и завершить рано

## Решение

### Изменение 1: Увеличение max_length при токенизации

**Метод `summarize_chunk()`:**
```python
# ПОСЛЕ ИСПРАВЛЕНИЯ
inputs = self.model_manager.qwen_tokenizer(
    prompt,
    return_tensors="pt",
    truncation=True,
    max_length=24000  # <-- УВЕЛИЧЕНО с 12000 до 24000
).to(self.model_manager.qwen_model.device)
```

**Причина:** Это даёт модели больше контекста, особенно для коротких файлов, где prompt занимает меньший процент от общей длины.

### Изменение 2: Добавление явного max_length в generate()

**Метод `summarize_chunk()`:**
```python
# ПОСЛЕ ИСПРАВЛЕНИЯ
with torch.no_grad():
    outputs = self.model_manager.qwen_model.generate(
        **inputs,
        max_new_tokens=max_tokens,
        max_length=len(inputs.input_ids[0]) + max_tokens,  # <-- НОВАЯ СТРОКА
        do_sample=False,
        num_beams=1,
        repetition_penalty=1.05,
    )
```

**Причина:** Явный `max_length` гарантирует, что модель будет генерировать ровно `max_tokens` новых токенов без преждевременного завершения.

### Дополнительные изменения

**Метод `merge_summaries()`:**
- Увеличено `max_length` при токенизации с 24000 до 32000
- Добавлен явный `max_length` в generate()

Причина: При объединении нескольких суммаризаций нужно больше контекста для корректной работы.

## Технические детали

### Параметры Qwen модели

- `max_new_tokens`: Максимальное количество **новых** токенов для генерации
- `max_length`: Максимальная **общая** длина последовательности (input + new tokens)
- Без явного `max_length`, модель может использовать внутренние эвристики для завершения

### Значения токенов

В русском языке приблизительно:
- 1000 символов ≈ 250-300 токенов
- Система prompt ≈ 200-300 токенов
- max_new_tokens для summarize_chunk = 800
- max_new_tokens для merge_summaries = 7000
