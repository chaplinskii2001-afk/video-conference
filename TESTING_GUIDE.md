# Руководство по тестированию оптимизаций

## Быстрая проверка

### 1. Запустите проект
```bash
docker-compose up -d
```

### 2. Проверьте логи при загрузке моделей
```bash
docker-compose logs app | grep -E "BetterTransformer|float16|batch_size"
```

**Ожидаемый результат:**
```
✅ BetterTransformer включен для Whisper (ускорение 20-30%)
PyAnnote segmentation модель переведена в float16
PyAnnote embedding модель переведена в float16
PyAnnote embedding batch_size установлен: 32
```

### 3. Загрузите файл для обработки
Используйте веб-интерфейс или API для загрузки медиа файла.

### 4. Следите за выполнением
```bash
docker-compose logs -f app | grep -E "WHISPER|PYANNOTE"
```

**Ожидаемый результат:**
```
🔄 [WHISPER] Начало транскрипции аудио...
🔄 [PYANNOTE] Начало диаризации аудио...
✅ [WHISPER] Транскрипция завершена: 245 сегментов за 45.23с
✅ [PYANNOTE] Диаризация завершена: 189 сегментов за 52.11с
```

### 5. Сравните время выполнения

**До оптимизаций (ориентировочно):**
- Whisper: ~60 секунд
- PyAnnote: ~90 секунд
- Итого: ~150 секунд

**После оптимизаций (ожидается):**
- Whisper: ~45 секунд (-25%)
- PyAnnote: ~40 секунд (-55%)
- Итого: ~85 секунд (-43%)

## Детальная проверка

### Проверка GPU использования

В отдельном терминале запустите:
```bash
watch -n 1 nvidia-smi
```

**Что наблюдать:**
- GPU Memory-Usage должна быть на 70-90% во время обработки
- GPU-Util должна быть на 90-100% во время обработки
- Обе модели должны использовать GPU одновременно (но выполняются последовательно)

### Проверка параллельности

Посмотрите временные метки в логах:
```bash
docker-compose logs app | grep -E "🔄 \[WHISPER\]|🔄 \[PYANNOTE\]"
```

**Что проверять:**
- Обе модели должны начать работу в течение 1-2 секунд друг от друга
- Это подтверждает параллельную подготовку данных

### Проверка качества

1. Сравните результаты транскрипции до и после оптимизаций
2. Количество сегментов должно быть примерно одинаковым
3. Точность распознавания должна быть > 99% от оригинала
4. Количество спикеров должно остаться тем же

### Проверка стабильности

Запустите несколько файлов подряд:
```bash
# Отправьте 3-5 файлов на обработку
```

**Что проверять:**
- Нет утечек памяти (memory usage не растёт)
- Скорость обработки остаётся стабильной
- Нет ошибок OOM (Out of Memory)

## Бенчмарки

### Тестовые файлы

Используйте файлы разной длительности:
- 5 минут (короткий)
- 15 минут (средний)
- 30 минут (длинный)

### Метрики для сравнения

Заполните таблицу:

| Длительность | До (сек) | После (сек) | Ускорение (%) |
|-------------|----------|-------------|---------------|
| 5 мин       |          |             |               |
| 15 мин      |          |             |               |
| 30 мин      |          |             |               |

### Расчёт ускорения

```
Ускорение = ((До - После) / До) * 100%
```

Ожидаемое ускорение: 35-50%

## Troubleshooting

### Оптимизации не применяются

**Проблема:** Не видите сообщений об оптимизациях в логах.

**Решение:**
1. Проверьте, что изменения применены:
   ```bash
   git diff config.py processing/model_manager.py processing/video_processor.py
   ```

2. Пересоберите контейнер:
   ```bash
   docker-compose down
   docker-compose build --no-cache
   docker-compose up -d
   ```

### BetterTransformer недоступен

**Проблема:** Видите предупреждение о недоступности BetterTransformer.

**Решение:**
1. Установите optimum:
   ```bash
   docker-compose exec app pip install optimum
   ```

2. Или игнорируйте - Whisper будет работать без этой оптимизации.

### OOM ошибки

**Проблема:** GPU память переполняется.

**Решение:**
1. Уменьшите batch_size в `config.py`
2. Уменьшите diarization_batch_size
3. Перезапустите:
   ```bash
   docker-compose restart app
   ```

### Медленная обработка

**Проблема:** Скорость не улучшилась.

**Решение:**
1. Проверьте GPU профиль:
   ```bash
   docker-compose logs app | grep "GPU профиль"
   ```

2. Проверьте, что GPU используется:
   ```bash
   nvidia-smi
   ```

3. Проверьте применение оптимизаций (см. выше)
