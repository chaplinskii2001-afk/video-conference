# Исправление проблемы с libcudnn_cnn

## Проблема

При запуске обработки видео PyTorch не может загрузить библиотеку cuDNN CNN:

```
Unable to load any of {libcudnn_cnn.so.9.1.0, libcudnn_cnn.so.9.1, libcudnn_cnn.so.9, libcudnn_cnn.so}
Invalid handle. Cannot load symbol cudnnCreateConvolutionDescriptor
```

Ошибка возникает при работе PyAnnote (диаризация), которая использует PyTorch с GPU.

## Корневая причина

Базовый Docker образ `nvidia/cuda:12.6.2-cudnn-runtime-ubuntu22.04` содержит только **минимальный cuDNN runtime**, который включает базовую библиотеку `libcudnn.so`, но **НЕ включает** полный набор модульных библиотек cuDNN 9:

- `libcudnn_cnn.so.9` - операции свертки (CNN)
- `libcudnn_ops.so.9` - базовые операции
- `libcudnn_adv.so.9` - продвинутые операции
- `libcudnn_graph.so.9` - операции графов

В cuDNN 9+ библиотека разбита на отдельные модули, и PyTorch требует полный набор для работы с GPU.

## Решение

Установить полный пакет cuDNN 9 для CUDA 12 в Dockerfile:

```dockerfile
# Установка полного набора библиотек cuDNN 9 для CUDA 12
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
    libcudnn9-cuda-12 \
    && rm -rf /var/lib/apt/lists/*
```

Этот пакет устанавливает все необходимые модульные библиотеки cuDNN 9, которые требуются PyTorch для работы с GPU.

## Измененные файлы

1. **`docker/Dockerfile`**:
   - Добавлена установка пакета `libcudnn9-cuda-12`
   - Выполняется после установки базовых зависимостей

2. **`test_cudnn.py`** (новый):
   - Скрипт для диагностики наличия библиотек cuDNN
   - Проверяет доступность всех необходимых `.so` файлов
   - Тестирует работу PyTorch с cuDNN

## Как это работает

1. **Базовый образ** предоставляет минимальный cuDNN runtime
2. **Дополнительный пакет** `libcudnn9-cuda-12` устанавливает полный набор библиотек
3. **PyTorch** теперь может найти все необходимые библиотеки через `LD_LIBRARY_PATH`
4. **PyAnnote** успешно выполняет операции на GPU без ошибок

## Альтернативные решения (не использованы)

1. **Использовать образ `cudnn-devel`** - содержит все библиотеки, но занимает значительно больше места
2. **Установить отдельные пакеты** - более сложно и требует точного знания версий

## Тестирование

Создан тестовый скрипт для проверки:

```bash
python3 test_cudnn.py
```

Скрипт проверяет:
- Наличие всех необходимых библиотек cuDNN
- Работоспособность PyTorch с cuDNN
- Выполнение тестовой операции Conv2d на GPU

## Результат

- ✅ Все библиотеки cuDNN 9 доступны в системе
- ✅ PyTorch успешно использует cuDNN для GPU операций
- ✅ PyAnnote выполняет диаризацию на GPU без ошибок
- ✅ faster-whisper (CTranslate2) продолжает работать корректно

## Важные замечания

- **НЕ удалять** `LD_LIBRARY_PATH` в Dockerfile - это критично для поиска библиотек
- Пакет `libcudnn9-cuda-12` совместим с образом `cuda:12.6.2-cudnn-runtime`
- CTranslate2 (faster-whisper) и PyTorch теперь корректно работают вместе на одном GPU
