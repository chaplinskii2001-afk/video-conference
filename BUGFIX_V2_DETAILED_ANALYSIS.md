# Второе исправление: Проблема с конфликтом параметров генерации

## Обнаруженная проблема

При анализе логов из первого исправления обнаружен критический warning:

```
Both `max_new_tokens` (=1200) and `max_length`(=4583) seem to have been set. 
`max_new_tokens` will take precedence.
```

**Это значит, что первое исправление было НЕПРАВИЛЬНЫМ!**

Я добавил `max_length` в параметры `generate()`, но это создало конфликт, который Transformers library разрешает в пользу `max_new_tokens`, игнорируя мой `max_length`.

## Анализ проблемы

### Что я сделал неправильно

В первом исправлении:
```python
outputs = self.model_manager.qwen_model.generate(
    **inputs,
    max_new_tokens=max_tokens,
    max_length=len(inputs.input_ids[0]) + max_tokens,  # <-- КОНФЛИКТ!
    do_sample=False,
    num_beams=1,
    repetition_penalty=1.05,
)
```

Transformers library не позволяет одновременно устанавливать `max_new_tokens` и `max_length` для causal language models, так как это создает неопределенность.

### Почему обрезание все еще происходит

Истинная причина обрезания **НЕ в max_length**, а в чем-то другом:

1. **Qwen модель может иметь встроенное ограничение на max_position_embeddings** (~32768 токенов)
2. **Модель может завершаться раньше из-за внутренней логики завершения** (EOS token, логика содержания)
3. **`min_new_tokens` не установлен** - модель может остановиться раньше, если считает ответ завершенным

## Правильное решение

### Изменение 1: Убрать конфликтующий `max_length`

**Было:**
```python
outputs = self.model_manager.qwen_model.generate(
    **inputs,
    max_new_tokens=max_tokens,
    max_length=len(inputs.input_ids[0]) + max_tokens,  # КОНФЛИКТ
    do_sample=False,
    num_beams=1,
    repetition_penalty=1.05,
)
```

**Стало:**
```python
outputs = self.model_manager.qwen_model.generate(
    **inputs,
    max_new_tokens=max_tokens,
    min_new_tokens=max(100, int(max_tokens * 0.8)),  # НОВОЕ
    do_sample=False,
    num_beams=1,
    repetition_penalty=1.05,
)
```

### Что это дает

- ✅ Убирает конфликт между параметрами
- ✅ Добавляет `min_new_tokens` для гарантии минимального выхода
  - Для `max_tokens=800`: минимум = max(100, 640) = 640 токенов
  - Для `max_tokens=1200`: минимум = max(100, 960) = 960 токенов
  - Для `max_tokens=7000`: минимум = max(500, 5600) = 5600 токенов

### Изменение 2: Добавить детальное логирование

**Было:**
```python
# Без логирования
```

**Стало:**
```python
input_length = len(inputs.input_ids[0])
self.logger.info(f"Суммаризация чанка: input_tokens={input_length}, max_new_tokens={max_tokens}")

# ... generate() ...

generated_ids = outputs[0][len(inputs.input_ids[0]):].tolist()
self.logger.info(f"Сгенерировано токенов: {len(generated_ids)} (ожидалось {max_tokens})")
```

**Зачем:**
- Позволяет видеть в логах, сколько токенов на самом деле было сгенерировано
- Помогает диагностировать проблемы с обрезанием
- Показывает разницу между ожидаемым и фактическим output

## Технические детали

### Параметры Qwen для generate()

| Параметр | Описание | Используется? |
|----------|---------|---------------|
| `max_new_tokens` | Максимум новых токенов | ✅ ДА |
| `min_new_tokens` | Минимум новых токенов | ✅ ДА (ДОБАВЛЕНО) |
| `max_length` | Общая максимальная длина | ❌ НЕТ (конфликт) |
| `do_sample` | Использовать выборку | ✅ ДА (False) |
| `repetition_penalty` | Штраф за повторение | ✅ ДА (1.05) |
| `num_beams` | Beam search | ✅ ДА (1) |

### Почему `min_new_tokens` работает лучше

`min_new_tokens` гарантирует, что модель будет генерировать **минимум** N токенов перед тем, как может остановиться. Это предотвращает преждевременное завершение:

```
ДО (без min_new_tokens):
Модель может остановиться на любом этапе, если сочтет ответ завершенным
→ Может быть 200, 400, 600 токенов вместо 800

ПОСЛЕ (с min_new_tokens=640):
Модель генерирует ВСЕ минимум 640 токенов, затем может остановиться
→ Будет минимум 640, максимум 800 токенов
```

## Почему это лучше решение

1. ✅ **Убирает конфликт параметров** - больше нет warning от Transformers
2. ✅ **Гарантирует минимальный выход** - модель не может остановиться слишком рано
3. ✅ **Добавляет отладку** - можно видеть реальное количество сгенерированных токенов
4. ✅ **Соответствует лучшим практикам** - используются правильные параметры для LLM

## Альтернативные подходы (если это все еще не работает)

Если проблема сохранится, потенциальные решения:

1. **Использовать `eos_token_id=None`** - отключить раннее завершение
2. **Увеличить `repetition_penalty`** - сделать более агрессивный штраф
3. **Уменьшить `max_length` при токенизации** - если GPU память проблема
4. **Использовать `forced_bos_token_id`** - зависит от модели
5. **Проверить встроенный max_position_embeddings Qwen** - может быть жесткое ограничение
