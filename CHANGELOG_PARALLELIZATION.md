# Changelog: Параллелизация Whisper и PyAnnote

## Версия: feat/parallelize-whisper-pyannote

### 🎯 Основная цель
Параллелизировать обработку речи (Whisper) и диаризации (PyAnnote) для сокращения времени обработки видеоконференций.

### ✨ Что было сделано

#### 1. Модуль `processing/model_manager.py`

**Модифицированные методы:**

- `load_whisper(skip_unload: bool = False)` 
  - Добавлен параметр `skip_unload` для управления выгрузкой предыдущей модели
  - При `skip_unload=True`, модель остается в памяти для параллельной работы
  - `current_loaded_model` не обновляется при параллельной загрузке

- `load_diarization(skip_unload: bool = False)`
  - Аналогичные изменения как для `load_whisper`
  - Позволяет загружать обе модели одновременно

**Новые методы:**

- `unload_whisper_and_diarization()` - асинхронный метод
  - Выгружает обе модели (Whisper и PyAnnote) одновременно
  - Используется после параллельной обработки
  - Гарантирует очистку памяти

#### 2. Модуль `processing/video_processor.py`

**Модифицированные методы:**

- `transcribe_audio(audio_path: str, skip_unload: bool = False)`
  - Добавлен параметр `skip_unload` для параллельной работы
  - Может работать с `skip_unload=True` без выгрузки модели

- `diarize_audio(audio_path: str, skip_unload: bool = False)`
  - Аналогичные изменения как для `transcribe_audio`

- `process_media()` - главный пайплайн
  - Обновлен для использования параллельной обработки
  - Вместо последовательных вызовов транскрипции и диаризации, 
    теперь вызывает `process_transcription_and_diarization_parallel()`

**Новые методы:**

- `process_transcription_and_diarization_parallel(audio_path: str) -> tuple`
  - Главный метод параллельной обработки
  - Загружает обе модели с параметром `skip_unload=True`
  - Запускает обе задачи обработки параллельно через `asyncio.gather()`
  - Ждет завершения обеих задач
  - Выгружает обе модели в блоке `finally`
  - Возвращает кортеж `(transcription_segments, diarization_segments)`

- `_transcribe_audio_parallel(audio_path: str) -> List[Dict]`
  - Вспомогательный метод для параллельной транскрипции
  - Используется внутри `process_transcription_and_diarization_parallel()`

- `_diarize_audio_parallel(audio_path: str) -> List[Dict]`
  - Вспомогательный метод для параллельной диаризации
  - Используется внутри `process_transcription_and_diarization_parallel()`

#### 3. Модуль `processing/stages.py`

**Новые этапы:**

- Добавлена стадия `"transcription_and_diarization"` (order: 6)
  - `display_name`: "Параллельная обработка"
  - `description`: "Распознавание речи (Whisper) и определение спикеров (PyAnnote) одновременно"
  - `icon`: "⚡"

**Обновлены порядки этапов:**

- `transcription` и `diarization`: перемещены на order: 6-7 (для обратной совместимости)
- `merging`: order 7 → 7
- `summarization`: order 9 → 8
- `saving`: order 10 → 9
- `completed`: order 11 → 10

### 🔄 Обратная совместимость

✅ **Сохранена**

Методы `transcribe_audio()` и `diarize_audio()` остаются функциональны и могут использоваться отдельно:

```python
# Старый способ (последовательный) - все еще работает
segments1 = await processor.transcribe_audio(audio_path)
segments2 = await processor.diarize_audio(audio_path)

# Новый способ (параллельный) - рекомендуется
segments1, segments2 = await processor.process_transcription_and_diarization_parallel(audio_path)
```

### 🛡️ Управление ошибками

- Если одна из моделей не загружается, выбрасывается исключение
- Обе модели гарантированно выгружаются в блоке `finally`
- Используется `asyncio.gather()` с `return_exceptions=False` для пробрасывания ошибок

### 🔧 Технические детали

#### Управление памятью

1. Обе модели загружаются с параметром `skip_unload=True`
2. `current_loaded_model` остается `None` во время параллельной работы
3. После завершения обе модели выгружаются одновременно методом `unload_whisper_and_diarization()`

#### Параллелизм

- Используется `asyncio.gather()` для одновременного выполнения двух задач
- asyncio переключается между задачами при I/O операциях
- Обе модели работают на одном GPU (если хватает памяти)

### 🚀 Как использовать

Система автоматически будет использовать параллельную обработку при запуске `process_media()`. Никаких дополнительных действий не требуется.

Для отслеживания прогресса параллельной обработки смотрите стадию `"transcription_and_diarization"` в логах.

### 🐛 Известные ограничения

1. Требует достаточно памяти GPU для одновременной загрузки обеих моделей
2. На GPU с малой памятью (<8GB) может возникнуть ошибка OutOfMemory
3. Параллелизм эффективен только при использовании GPU
