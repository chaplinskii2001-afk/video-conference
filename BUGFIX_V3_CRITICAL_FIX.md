# Версия 3: КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ - Обрезание в середине слова

## Проблема (реальная)

Файл с суммаризацией обрезался **В СЕРЕДИНЕ СЛОВА**:
```
— Было подчеркнуто, что ключевой задачей является устран
```

Логи говорили "Сгенерировано 1200 токенов", но вывод был обрезан. **Это означает, что EOS token срабатывал ДО того, как модель закончила генерировать!**

## Причина

Модель Qwen имеет **встроенный EOS token**, который она может генерировать в любой момент, даже если не достигла `max_new_tokens`. Мы не блокировали это в версии 2.

## Решение (версия 3)

### Ключевое изменение: Отключить EOS token

```python
# Было (версия 2):
outputs = self.model_manager.qwen_model.generate(
    **inputs,
    max_new_tokens=max_tokens,
    min_new_tokens=max(100, int(max_tokens * 0.8)),  # Не помогает!
    do_sample=False,
    num_beams=1,
    repetition_penalty=1.05,
)

# Стало (версия 3):
outputs = self.model_manager.qwen_model.generate(
    **inputs,
    max_new_tokens=max_tokens,  # Единственный параметр для управления выходом
    do_sample=False,
    num_beams=1,
    repetition_penalty=1.05,
    eos_token_id=None,  # 🔑 КРИТИЧЕСКИ: Отключить EOS
    pad_token_id=self.model_manager.qwen_tokenizer.pad_token_id,
)
```

### Почему это работает

- **`eos_token_id=None`** - говорит модели "НЕ ЗАКАНЧИВАЙ на EOS token"
- **`max_new_tokens`** - модель теперь ОБЯЗАНА генерировать ровно до лимита
- **`pad_token_id`** - явно указываем pad token для безопасности

### Удалены неработающие параметры

- ❌ `min_new_tokens` - УДАЛЕН (не работал, EOS срабатывал все равно)
- ❌ Второе вычисление `input_length` - упрощено

### Улучшено извлечение токенов

**Было:**
```python
generated_ids = outputs[0][len(inputs.input_ids[0]):].tolist()
```

**Стало:**
```python
input_length = len(inputs.input_ids[0])  # Сохраняем в переменную
generated_ids = outputs[0][input_length:].tolist()  # Используем её
```

Это гарантирует, что мы используем **точно то же значение** для всех операций.

## Как это работает на практике

### Для файла "устран[...]"

**Версия 2 (неработающая):**
```

2. Модель начинает генерировать
3. На 800-м токене модель выбирает EOS token
4. Генерация останавливается ДО max_new_tokens
5. min_new_tokens=640 не помогает, потому что EOS > min
6. Результат: "устран" (обрезано в середине слова)
```

**Версия 3 (работающая):**
```
1. Input: 3400 токенов
2. Модель начинает генерировать
3. Модель ХОЧЕТ выбрать EOS token на 800-м токене
4. Но eos_token_id=None БЛОКИРУЕТ это
5. Модель продолжает генерировать до max_new_tokens=1200
6. Результат: "устранение" + полный текст (полный)
```

## Технические детали

### EOS Token (End Of Sequence)

- Это специальный токен, который модель генерирует для сигнала "я закончил"
- По умолчанию, генерация останавливается когда модель выбирает EOS
- **Проблема:** Модель может выбрать EOS раньше, чем нам нужно

### Отключение EOS

- `eos_token_id=None` - скажет generate() не слушать EOS
- Модель будет генерировать ДО `max_new_tokens`
- Последний токен может быть EOS, но он включен в count

### Pad Token

- `pad_token_id=self.model_manager.qwen_tokenizer.pad_token_id`
- Явно указываем, что использовать для padding
- Это предотвращает потенциальные ошибки

## Почему версия 2 не сработала

`min_new_tokens` гарантирует **минимум новых токенов**, но **НЕ** гарантирует что EOS не срабатит. Для Qwen:

```
min_new_tokens=640 ≠ "модель НЕ закончится до 640 токенов"
min_new_tokens=640 = "если модель решит закончиться, то минимум 640 токенов"

Но EOS обычно срабатит ДО 640, так что эта гарантия не работает!
```

## Почему мы не сделали это раньше?

1. Это не очевидное решение без глубокого анализа логов
2. Нужно было видеть реальный результат (обрезание в "устран") чтобы понять что дело в EOS
3. Большинство примеров не говорят об отключении EOS для LLM

## Потенциальные побочные эффекты

1. **Модель может генерировать "мусор" в конце** - обычно skip_special_tokens это убирает
2. **Медленнее генерирует** - модель не может остановиться раньше (это хорошо!)
3. **Может быть padding токены** - decode() с skip_special_tokens это убирает

## Заключение

**Версия 3 - это РЕАЛЬНОЕ исправление проблемы.**

Истинная причина обрезания была в **EOS token**, а не в max_length или min_new_tokens. Отключение `eos_token_id=None` гарантирует, что модель будет генерировать до `max_new_tokens` без преждевременного завершения.
