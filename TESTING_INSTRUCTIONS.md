# Инструкция по тестированию исправления обрезания суммаризации

## Подготовка

### 1. Убедиться что код применен
```bash
cd /home/engine/project

# Проверить что файл содержит новые строки
grep -n "min_new_tokens" processing/video_processor.py
# Должны вывести:
# 449:                min_new_tokens=max(100, int(max_tokens * 0.8)),
# 512:                min_new_tokens=max(500, int(max_new_tokens * 0.8)),
```

### 2. Пересобрать Docker образ
```bash
docker-compose down
docker-compose build --no-cache
docker-compose up -d

# Проверить что контейнер запустился
docker-compose ps
```

### 3. Подождать загрузки моделей
```bash
docker-compose logs -f app | grep -E "загружен|Ошибка"
# Должны увидеть "✅ Whisper загружен успешно" и т.д.
```

## Тестирование

### Тест 1: Короткий файл (5-10 минут)

#### 1.1 Загрузить файл
```bash
# Через веб-интерфейс:
# http://localhost:8000
# 1. Выбрать файл 5-10 минут
# 2. Выбрать тип "protocol"
# 3. Нажать "Обработать"

# Или через curl:
curl -X POST http://localhost:8000/process \
  -F "file=@short_video.mp4" \
  -F "summary_type=protocol"
```

#### 1.2 Получить task_id
```bash
# Ответ должен быть примерно:
# {"task_id": "abc-123", "status": "processing"}
```

#### 1.3 Мониторить логи
```bash
docker-compose logs -f app | tail -50

# Ожидаемые строки:
# 2025-12-13 14:30:09 - INFO - Суммаризация чанка: input_tokens=3400, max_new_tokens=1200
# 2025-12-13 14:31:06 - INFO - Сгенерировано токенов: 1200 (ожидалось 1200)

# НЕПРИЕМЛЕМЫЕ строки (признак проблемы):
# Both `max_new_tokens` and `max_length` seem to have been set
# Сгенерировано токенов: 800 (ожидалось 1200)  ← Обрезано!
```

#### 1.4 Проверить результат
```bash
# Дождаться завершения (ЗАДАЧА ЗАВЕРШЕНА в логах)

# Скачать результат
curl http://localhost:8000/download/abc-123/summary -o summary.md

# Проверить содержимое
cat summary.md | head -100
# Должны быть все разделы:
# - Дата проведения:
# - Присутствуют:
# - Повестка дня:
# - Рассмотрены вопросы и решения:
# - Итоги:

# Проверить что не обрезано
wc -c summary.md
# Должно быть > 2000 символов для 5-10 минут
```

### Тест 2: Длинный файл (30+ минут)

Повторить всё как в Тест 1, но с файлом 30+ минут.

**Ожидаемый результат:**
```
Обработка файла 30 минут:
- Суммаризация разбита на несколько частей (>1)
- Логи покажут: Объединение суммаризаций
- Логи покажут: Сгенерировано токенов: 7000
```

### Тест 3: Проверка логирования

```bash
# Собрать все логи суммаризации
docker-compose logs app | grep -E "Суммаризация|Объединение|Сгенерировано" > summarization.log

# Проверить что логирование полное
cat summarization.log | grep "Сгенерировано"
# Должны увидеть:
# - Для каждого чанка: "Сгенерировано X (ожидалось 800 или 1200)"
# - Для объединения: "Сгенерировано Y (ожидалось 7000)"
```

## Проверочный лист

### Для коротких файлов
- [ ] Логи содержат "Суммаризация чанка: input_tokens=..."
- [ ] Логи НЕ содержат warning о конфликте параметров
- [ ] Логи показывают "Сгенерировано токенов: 1200 (ожидалось 1200)"
- [ ] Summary файл полный (все разделы присутствуют)
- [ ] Summary файл не обрезан в середине предложения
- [ ] Summary > 2000 символов

### Для длинных файлов
- [ ] Логи показывают "Объединение суммаризаций"
- [ ] Логи показывают "Сгенерировано токенов: 7000 (ожидалось 7000)"
- [ ] Summary содержит информацию из всех частей
- [ ] Summary не содержит дублирования
- [ ] Summary > 4000 символов

## Если что-то не работает

### Проблема 1: Summary все еще обрезан
```bash
# 1. Проверить что изменения применены
grep "min_new_tokens" processing/video_processor.py | wc -l
# Должно быть 2 совпадения

# 2. Пересоберить Docker
docker-compose down
docker-compose build --no-cache
docker-compose up -d

# 3. Проверить логи
docker-compose logs app | grep -E "Сгенерировано" | tail -5
# Если сгенерировано < ожидалось, проблема в min_new_tokens

# 4. Проверить что нет OOM
docker-compose logs app | grep -i "cuda\|oom\|memory"
```

### Проблема 2: Warning о конфликте параметров
```bash
# Значит версия 1 все еще используется
docker-compose logs app | grep "max_new_tokens\|max_length" | head -5

# Решение: Пересоберить с --no-cache
docker-compose build --no-cache
```

### Проблема 3: Медленнее работает
```bash
# Это нормально, так как модель генерирует больше токенов
# Мониторить прогресс:
docker-compose logs -f app | grep "%\|Прогресс"

# Если зависает > 2 часа на коротком файле - проблема
```
