# Исправление Race Condition в параллельной обработке

## Описание проблемы

После внедрения параллелизации Whisper и PyAnnote возникла критическая ошибка:

```
RuntimeError: Whisper pipeline не загружен
```

### Логи ошибки

```
Загрузка Whisper модели...
✅ Whisper загружен успешно
Загрузка PyAnnote модели...
✅ PyAnnote загружен успешно
Обе модели загружены, запуск параллельной обработки...
❌ Ошибка транскрипции: Whisper pipeline не загружен
```

**Парадокс**: Модель успешно загружена, но система считает, что она не загружена!

## Причина ошибки

### Код до исправления

В файле `processing/model_manager.py` метод `whisper_transcribe()` содержал две проверки:

```python
def whisper_transcribe(self, audio_path: str) -> Dict:
    if self.whisper_pipeline is None or self.current_loaded_model != "whisper":
        raise RuntimeError("Whisper pipeline не загружен")
    # ...
```

### Проблема

1. При параллельной загрузке вызывается `load_whisper(skip_unload=True)`
2. Whisper успешно загружается: `self.whisper_pipeline` становится валидным объектом
3. **НО**: из-за `skip_unload=True`, переменная `self.current_loaded_model` НЕ обновляется (остается `None`)
   ```python
   # В методе load_whisper()
   if not skip_unload:
       self.current_loaded_model = "whisper"  # Эта строка НЕ выполняется!
   ```
4. Когда вызывается `whisper_transcribe()`:
   - `self.whisper_pipeline is None` → **False** (pipeline существует)
   - `self.current_loaded_model != "whisper"` → **True** (потому что None != "whisper")
5. Результат: Проверка **ПАДАЕТ**, хотя pipeline загружен и готов к работе!

### Почему `current_loaded_model` не обновляется?

Переменная `current_loaded_model` используется для **последовательного** управления моделями:
- Когда загружается новая модель, выгружается старая
- `current_loaded_model` отслеживает, какая модель сейчас активна

При **параллельной** загрузке:
- Обе модели загружаются одновременно
- Концепция "текущая модель" не применима
- Поэтому `current_loaded_model` остается `None`

## Решение

Удалена избыточная проверка `current_loaded_model` из метода `whisper_transcribe()`:

### Код после исправления

```python
def whisper_transcribe(self, audio_path: str) -> Dict:
    if self.whisper_pipeline is None:
        raise RuntimeError("Whisper pipeline не загружен")
    # ...
```

### Почему это правильно?

1. **Достаточная проверка**: Наличие `self.whisper_pipeline` полностью определяет, можно ли использовать Whisper
2. **Работает для обоих режимов**:
   - Последовательная загрузка: pipeline загружен, проверка пройдена ✅
   - Параллельная загрузка: pipeline загружен, проверка пройдена ✅
3. **Обнаружение ошибок**: Если модель не загружена, `pipeline` будет `None` и ошибка будет обнаружена

## Влияние исправления

### Что изменилось
- Метод `whisper_transcribe()` теперь проверяет только наличие pipeline объекта
- Удалена зависимость от `current_loaded_model`

### Что НЕ изменилось
- Логика загрузки/выгрузки моделей
- Параметр `skip_unload` работает как прежде
- Последовательная загрузка работает как прежде
- Обратная совместимость сохранена

### Затронутые файлы
- `processing/model_manager.py` - одна строка изменена (line 214)

## Выводы

### Урок
При реализации параллелизации нужно пересмотреть все проверки состояния, которые были разработаны для последовательного выполнения.

### Рекомендации
- Проверки должны базироваться на **реальном состоянии** объектов, а не на метаданных управления
- Переменные типа `current_loaded_model` - это служебные данные для оптимизации, не для проверки корректности
- При добавлении параллелизма всегда проверяйте все методы, которые используют загруженные ресурсы
